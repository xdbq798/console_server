## Apipost 登录 403 排查

- 报错 `{"detail":"缺少会话操作保护请求头"}` 来自 `src/console_server/api/auth.py:132-152` 的 `validate_cookie_request()`。

## 日志系统接入 loguru（方案 B）

- 依赖：`uv add loguru`，同时 `uv remove colorama`（原彩色 print 体系退役）
- 新增 `core/logger.py`：InterceptHandler 把标准库 logging 全量转发给 loguru（uvicorn/apscheduler/sqlalchemy 一并收编）；setup_logging() 读 `GLOBAL_LOG_LEVEL` / `LOG_FORMAT`（json=结构化），NO_COLOR 或 RUNNING_IN_DOCKER 时关彩色
- 保留 env.py 的 `SRC_LOG_LEVELS` 机制：loguru 用 `logger.bind(log_source=...)` + sink filter 实现，`module_logger(source)` 是新入口；模块日志等级从对应 `XXX_LOG_LEVEL` 环境变量读
- 坑 1：InterceptHandler 帧回溯深度必须数完调用链上所有 `logging.__file__` 帧（depth = 1 + 计数），否则显示 `logging:callHandlers` 而非真实调用方
- 坑 2：Starlette 后注册的中间件先执行；RequestLoggingMiddleware 要在 AuthMiddleware 之后 add_middleware 才能记到 401 等被认证层拦截的请求
- 新增 `middleware/request_logging.py`：每请求一行日志（方法 路径 -> 状态 耗时ms），响应头带 `X-Request-ID`（uuid 前 8 位），5xx 记 WARNING
- `utils/console.py` 的 print_* 保留为 loguru 适配层（`logger.opt(depth=1)` 保证定位到真实调用方），db/database.py、api/auth.py 调用方零改动
- main.py：setup_logging() 必须在所有本地/第三方模块导入前调用；print_* 换 log.success/warning/info；`log.error(..., exc_info=True)` 换 `log.exception(...)`
- 已验证：启动横幅、uvicorn access log、apscheduler 日志全部统一 loguru 格式；请求日志带耗时和 request_id；`GLOBAL_LOG_LEVEL=WARNING` 过滤与 `LOG_FORMAT=json` 输出均正常
- README 与 docs/后端启动教程.md 环境变量表补充 LOG_FORMAT / NO_COLOR

## WebSocket（Socket.IO）集成

- 选型：python-socketio（依赖本就在 pyproject），async_mode="asgi"，rooms 按 user_id 分组推送
- 新增 `src/console_server/ws/`：server.py（AsyncServer 实例，配置了 AUTH_ALLOWED_ORIGINS 白名单）、auth.py（握手 token 提取 + authenticate_socket 复用 _get_user_from_token，任何异常返回 None）、manager.py（push_to_user / broadcast 推送封装，失败只告警不抛）、events.py（connect/disconnect/ping 注册，connect 返回 False 拒绝连接）
- 关键坑 1：**不能 `app.mount("/socket.io", socketio.ASGIApp)`**——ASGIApp 内部按 `scope['path'].startswith('/socket.io')` 分发，Starlette Mount 剥前缀后内层永远 404。正确做法：`socket_app = SocketASGIApp(sio, other_asgi_app=app, socketio_path=settings.WS_PATH)` 包裹整个应用，uvicorn 入口改 `console_server.main:socket_app`（scripts/start.py 已改）
- 关键坑 2：AuthMiddleware（BaseHTTPMiddleware）只拦 HTTP，Socket.IO 握手不经过它，认证必须在 connect 事件里独立做；token 走 auth 负载/查询参数/Authorization 头（浏览器 WS 不能带自定义 header）
- 关键坑 3：异步版 `sio.enter_room`/`save_session` 都是协程必须 await，且 save_session 需真实连接（单测不能用假 sid）；`AsyncManager()` 替换 manager 后必须 `set_server(sio)`
- 多 worker：配置 REDIS_URL 时自动用 AsyncRedisManager(write_only=True) 跨进程广播，未配置降级单进程（与黑名单降级策略一致）
- 配置：config.py 新增 `WS_PATH`（默认 socket.io）；pyproject dev 组新增 aiohttp（socketio 测试客户端需要）；server 端 uvicorn 的 WS 支持靠 wsproto（已是传递依赖）
- 测试：`tests/test_ws.py` 13 个用例全过——单元层（token 提取、认证通过/垃圾/refresh 误用/黑名单/撤销会话）+ 全链路（进程内 uvicorn + socketio.AsyncClient 真实握手、拒绝路径、按房间推送）。测试用内存 SQLite + _PatchedSessionFactory 替换 database.AsyncSessionLocal
- 启动验证：start.py --dry-run 确认入口已是 main:socket_app；全量 175 测试仅 5 个 DockerStartupTests 失败（REDIS_PASSWORD 缺失，stash 验证为改动前既有环境问题，与本次无关）
- 推送用法：业务代码 `from console_server.ws.manager import push_to_user; await push_to_user(user_uuid, "event", data)`
